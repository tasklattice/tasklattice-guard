# Runner-to-Controller HTTP scope: integration design

Status: implementation in progress, not a claim of complete HTTP scoping. The opt-in pool-token map constrains the Runner **gRPC control stream** and model-credential HTTP authentication; candidate validation leases are bound to the selected pool. An independently enabled telemetry mode authenticates the sending pool and quarantines unsupported origins. Separate per-pool Controller-to-Runner HTTP credentials are now optional; active model credentials remain platform-wide. See the [credential mode matrix](runner-http-pool-credentials.md) for exact configuration, rollout and remaining limitations.

## Current boundaries

- `controller/server/control-channel/control-server.ts` authenticates the optional configured pool token before accepting a claimed pool. The shared principal authenticator is also used by model-credential HTTP resolution.
- By default, `/api/internal/v1/runtime-events` uses the legacy token. Enabling `CONTROLLER_RUNNER_SCOPED_TELEMETRY=true` requires a configured pool-token map, accepts only a matching pool bearer, and rejects the legacy bearer. Set `GUARD_RUNNER_SCOPED_TELEMETRY=true` and `GUARD_RUNNER_CONTROL_TOKEN` on each upgraded Runner so its exporter sends its pool token. Both flags are explicit and default false. Mixed old/new Controllers and Runners do not form a secure rollout: old writers can still use legacy ingestion and missing or mismatched flags can cause rejected telemetry. Coordinate all senders and Controllers; this mode has not been deployed.
- Scoped ingestion attributes Playground events and their costs only when the Controller-minted invocation belongs to the authenticated pool and the remaining invocation checks pass. Authenticated Endpoint runtime events, costs and routing assignments/completions now use [persisted immutable snapshot contexts](endpoint-telemetry-contexts.md). Older invocations with no pool, mismatched pools and Endpoint/routing events lacking a matching context remain platform-only. Pool authentication does not establish a unique Runner or boot; all scoped per-Runner watermarks are suppressed. Routing completions cannot enrich quarantined assignments in this mode.
- Because unsupported Endpoint/routing telemetry is quarantined and no scoped watermark is authenticated, tenant dashboards omit that evidence. Router distribution always reports delayed/unavailable; deletion safety reports telemetry stale even when no Router is bound; and database-backed Runner telemetry-age metrics report unavailable. Existing legacy watermark rows, including writes by mixed-version Controllers, do not make those checks current. This is an intentional availability limitation, not a production-ready monitoring boundary.
- `CONTROLLER_RUNNER_HTTP_TOKENS_JSON` and `GUARD_CONTROLLER_HTTP_TOKEN` optionally separate inbound Runner HTTP authority by pool, with no fallback to the global bearer or another pool. `runner/control_client.py` uses `GUARD_RUNNER_CONTROL_TOKEN` for gRPC and model-credential resolution, falling back to the legacy token only in compatibility mode. Scoped telemetry is independent. Runners may omit the legacy secret only when the control token, distinct inbound HTTP token and scoped telemetry are all configured; the chart supports that composition. This does not remove scoped telemetry's quarantine/freshness limitations or global provider access.
- Active data-plane model configuration is global and is sent to all pools. `ModelConfigurationService.resolveCredentials` allows refs in that global active configuration. Candidate validation leases are bound to the selected pool before dispatch, but not to an individual Runner/boot and are process-local. Global bindings mean same provider refs may legitimately be authorized for multiple pools today; there is no per-group model assignment yet.
- New Playground invocation records store the pool/group selected for their Runner client, along with tenant, Guardrail and expiry; pre-migration records have unknown pool/group and no record has an allocation epoch yet. Draft previews are bound to their preparation allocation. In scoped mode the recorded pool must match the authenticated sender; legacy mode continues using its existing attribution rules. The selection snapshot does not fence a move between selection and dispatch; safe reassignment requires the pending epoch/lease work. A valid event may arrive after a tenant is moved; checking only the *current* group can reject legitimate delayed events. Runtime Endpoint and routing batches still lack equivalent immutable provenance and are quarantined.

## Safe incremental sequence

1. **Shared principal abstraction.** Move the existing constant-time control-channel token resolution into one internal authenticator returning an explicit `legacy` or `{poolId}` principal. Use it for gRPC and unit-test exact equivalence. Keep HTTP's current behavior unchanged in this refactor. A pool token identifies a shared pool principal, not a cryptographically unique Runner process. Neither incoming `runnerId`, pool ID, HTTP headers nor body claims are identity by themselves.
2. **Immutable invocation provenance.** Capture the selected pool/group (and, once implemented, allocation epoch) from the same `poolForTenant` result that selects the Playground Runner. Persist those values with the Controller-minted invocation ID before dispatch. For endpoint requests, design equivalent auditable allocation/pin provenance; do not infer authorization for a late event from today's group alone. Extend the event and routing contracts only with a server-verifiable opaque reference or signed context; never accept client-supplied tenant IDs as authority. Plan expiry, replay, key rotation and safe retention for retry windows.
3. **Atomic event authorization.** When scoped HTTP mode is enabled, require the pool principal on the batch and validate each event's trusted invocation/pin against that principal and epoch, endpoint/router, event type and allowed timestamp *inside the same transaction or with a correctly synchronized immutable snapshot*. Validate the body Runner/watermark identity against the pool's registration; a pool credential alone does not prove a boot or Runner instance. Check routing and cost-only events as well as normal runtime events, and prevent duplicate/enrichment events from crossing tenant or pool boundaries. Fail closed or place unattributable events in a platform-only quarantine. Design batch acknowledgement/dead-letter behavior so one poison event cannot cause endless retries or make other valid events disappear. Never silently map unknowns to tenantA.
4. **Model credentials.** Change resolution to accept a trusted principal. Filter requested refs against the exact data-plane model configuration actually authorized and assigned to that pool at a known generation. Until per-group model bindings exist, the globally active bindings remain intentionally shared; document this as platform-wide access and do not call it tenant-scoped provider isolation. Bind each validation credential lease to the selected pool and preferably Runner/boot and request ID **before** the request is dispatched, with expiry, revocation, exact provider refs, and one-time or explicitly bounded retry semantics. A pool credential or guessed lease ID must never redeem another pool's lease. Ensure failed dispatch and timeouts revoke it.
5. **Separate roles and migrate.** Add a dedicated scoped Runner HTTP credential (which may initially reuse that pool's gRPC token, subject to rotation policy), and a separate Controller-to-Runner authority that cannot be used by Runners to impersonate the Controller for another group. Update Runner telemetry exporter and `_model_credentials`; update Controller clients for pool-bound destination identity. Provision per-pool credentials via secrets/workload identity, not plaintext in Helm values or logs. Capability-negotiate and roll out new Controller and Runners together; only enable enforcement after all senders and historical retry paths are compatible. On enforcement, reject the legacy shared bearer for Runner HTTP—no fallback that undermines the boundary. Drain old Runners and verify affected internal APIs before claiming secure mode. The present global Controller secret must no longer be delivered to Runners.
6. **Leases and reassignment.** Integrate the serving-lease/allocation-epoch work and enforce moves against every old lease. Authentication alone does not fence a disconnected Runner. A malicious Runner that ignores its lease requires network/workload-level fencing for that threat model.

## Required tests before enabling enforcement

- Two pools with distinct tokens: correct stream + HTTP paths pass; shared legacy/unknown tokens and cross-pool Endpoint, Router, Guardrail invocation, Runner/watermark, event, cost and model refs fail or quarantine, with no leaked response data.
- Real HTTP + PostgreSQL tests for Endpoint events, shared C Guardrail invoked by A, Playground and validation, routing events, empty batches, mixed valid/invalid batches, async replay and duplicate IDs. Verify prior-group telemetry after reassignment against the recorded allocation/epoch, not against a forged pool field or a changed current membership.
- Validation lease assigned to pool A: A can redeem only authorized refs before expiry; B, wrong runner/boot, wrong provider, stale/replayed or revoked lease fail. Test timeout, failed dispatch, Controller restart and retry policy. Ensure tenant-owned model refs do not leak through global assignments.
- Secret rotation/revocation, startup without all pool credentials, mixed old/new versions, no-legacy enforcement, Controller-to-Runner authority, transport security and no secret output. Test all relevant generated API/protocol contracts and build.
- One-way partition, concurrent tenant move and telemetry ingestion, Controller failover and stale acknowledgements. Explicitly record expected data availability when enforcement quarantines stale/ambiguous evidence.

## Implementation checkpoints

- [x] Opt-in pool-bound gRPC token map and cross-pool registration rejection; optional Runner gRPC token; security caveat documented.
- [x] Reusable authenticated principal for gRPC and model-credential HTTP authentication.
- [x] Playground dispatch records the selected pool/group before sending to the selected client; historical mappings stay unknown, and draft previews fail if their allocation changes.
- [x] Optional pool-authenticated telemetry accepts verifiable Playground attribution and quarantines unsupported origins; existing watermarks are not trusted in that mode.
- [x] Pool/group/epoch-backed immutable Endpoint snapshot context for authenticated runtime events and costs.
- [x] Frozen Endpoint/Router/route/target provenance for routing assignments and completions, with immutable enrichment and no historical promotion.
- [ ] Authenticated session/boot and completeness proof for scoped watermarks and every remaining origin.
- [ ] Atomic scoped runtime/routing event ingestion and watermark handling.
- [ ] Pool/runner-bound validation leases and pool-assigned credential refs.
- [x] Optional separate per-pool Controller-to-Runner authority, Runner HTTP token wiring, Secret references and fail-closed configuration; complete scoped composition may omit the legacy secret from Runners. Coordinated deployment remains unverified.
- [ ] Adversarial integration tests, migration, documentation and deployment validation.

The optional mode deliberately limits what can be attributed until the remaining provenance, watermark and fencing work is complete. The default legacy mode maintains compatibility but does not provide a group-secure telemetry boundary.
