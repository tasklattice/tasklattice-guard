When the model streams chunks, complete the Input check first. Then submit each new text increment to `POST {endpoint}/guardrails/output-stream` on the same Endpoint. This is **JSON request → JSON response**, not SSE or WebSocket; the gateway owns the client-facing stream.

<a id="gateway-stream-request" />

## Submit ordered increments

```json
{"protocol":"litellm","call_id":"call-123","stream_id":"stream-456","sequence":0,"text":"Hello ","final":false}
```

- Send `protocol: "litellm"` explicitly; the default protocol does not match this Endpoint.
- Use the Input check's `litellm_call_id` as `call_id`. Give each new output stream a new `stream_id` and never reuse an ended ID.
- Start `sequence` at 0 and increment by exactly 1, with at most one request in flight per stream.
- Send only **new** text in `text`, not a cumulative prefix. On normal completion submit `final: true`, optionally with an empty final increment.

<a id="gateway-stream-delivery" />

## Deliver only released_text

Validate `stream_id`, `sequence`, `next_sequence`, field types, and the actual `mode` before delivering each response. Append only `released_text` once. Neither the raw model chunk nor nested diagnostic fields authorize delivery.

| `status` | Gateway behavior |
| --- | --- |
| `buffering` | Deliver no new text; wait for another increment or final submission |
| `released` | Deliver only this response's `released_text`, then continue in sequence |
| `completed` | Deliver remaining `released_text` and finish; submit nothing more |
| `blocked` | Deliver no new text; stop the stream and client delivery, and cancel upstream generation if supported |

Published Policies determine the actual `mode`: `full_buffered` waits for a successful final check; `window_buffered` may release increments while retaining a trailing window; `interruptible` may release after each check but cannot retract previously delivered text. If the whole response must pass before any character is shown, require the actual mode to be `full_buffered`. Chunk requests cannot choose a mode.

<a id="gateway-stream-end" />

## Complete or stop

On normal model completion, submit `final: true` even if no new text remains and wait for a valid `completed` response before claiming protected completion. `[DONE]`, SSE closure, and disconnects do not replace that submission. `terminate: true` can arrive before `final: true`; send no more chunks after termination. On timeout or lost response, do not blindly replay: the server may have accepted the sequence, and the protocol has no general idempotent retry or recovery cursor. See [failure handling and production checks](#gateway-failures).
