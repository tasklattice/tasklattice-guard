Use a `user` account to create and manage business Guardrails. Platform administrators prepare shared services and maintain the Default baseline. See [account roles](/document/admin/platform-access#admin-governance).

<a id="guardrail-build-steps" />
## Compose and test the draft

1. Review available Policies in the [Policy Library](/policy-library). Inspect their Rules, parameters and Test Cases.
2. Create a Guardrail for the business scenario. Select exact Policy Versions.
3. Review enabled Rules, inspection stages, parameter values and action overrides.
4. Add normal, unsafe and boundary examples.
5. Run the current draft's tests. Inspect the resulting Testing Report.

A successful compilation alone does not prove detection behavior. Resolve test failures before publication.

<a id="guardrail-publish-steps" />
## Publish and connect traffic

1. Publish the tested draft as an immutable Guardrail Version.
2. Create an Endpoint for the application or gateway.
3. Target the exact version through a Router Route. Retain the final fallback.
4. Submit the routing change for approval by a different authorized user.
5. Confirm that Runners applied the published configuration.
6. Send real application requests. Check returned Decisions and actual content delivery.

The application owns model calls and must apply blocking or replacement. See [Endpoint integration](/document/developer/endpoint-setup) and [routing approval](/document/operator/operator-routing).

<a id="guardrail-build-readiness" />
## Check readiness and improve behavior

A Guardrail is ready when it retains a Released version with executable Artifact content. Readiness does not prove that the working draft passed tests or that traffic uses the version.

Imported versions start Pending. Run their frozen tests in this environment. Release them explicitly after passing.

Use [Playground](/playground) for trials and [runtime logs](/logs) for actual request evidence. Publish a new version after changing protection behavior. Existing Router Targets keep their pinned versions until a reviewed routing change updates them.

See [lifecycle and evidence rules](/document/overview/term-guardrail#state-guardrail-readiness) for capacity, deletion and restoration.
