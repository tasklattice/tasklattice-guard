Before calling an API operation, check its permissions, idempotency, and retry guidance in OpenAPI. A network timeout means that the client did not receive a result. It does not prove that the server did nothing.

<a id="api-contract-annotations" />
## Read the three OpenAPI annotations

- `x-token-permission` identifies the required module and read or write permission.
- `x-idempotency` describes what happens when the same request is sent again. For example, Router publication identifies duplicate requests with the `idempotencyKey` in the request body.
- `x-retry-policy` tells you whether to read the current state first or retry, and which request values must remain unchanged.

These `x-` fields describe an OpenAPI operation. They are **not** HTTP headers to send. Follow the request definition for the operation's actual parameters.

<a id="api-contract-async" />
## Check the result after `202`

`202 Accepted` means the request was accepted, but asynchronous work may still be running. For example, after you start a Guardrail test run, use the returned `runId` with `GET /api/v1/test-runs/{runId}` to read its Testing Report. Do not report “tests passed” from `202` alone.

<a id="api-contract-router-publish" />
## Change a Router by revision, then decide whether to retry

1. Read the Router and confirm the current draft and its revision.
2. Save the draft with `PUT /api/v1/routers/{id}/draft`. If the response is lost, read the draft again and compare its contents. Do not substitute a newer `expectedDraftRevision` without review.
3. Call `POST /api/v1/routers/{id}/publication-preview` and review the versions and Endpoint bindings that will be published. A repeated preview may differ if those references changed.
4. Submit the change: `POST /api/v1/routers/{id}/change-requests` with the reviewed `expectedDraftRevision`, `reviewedSnapshot`, `reviewedEndpointIds`, a `reason`, and an optional change `ticket`. Nothing is published yet.
5. Another administrator approves it: `POST /api/v1/routers/{id}/change-requests/{changeId}/approve`. Approval publishes exactly the submitted snapshot. In an emergency, `.../emergency-apply` requires a reason, applies it without a second approver, and records the reason and applying administrator.

If a submission times out, read the Router: `pendingChangeRequest` shows a submission that succeeded. If an approval times out, the same approver can repeat it. Check `publication.replayed` and the revision before you do anything else. For every other `POST`, check `x-retry-policy`. For example, starting a test run is not guaranteed to be idempotent. Do not retry it automatically after an uncertain response.

<a id="api-contract-resource-ids" />
## Find results by resource ID

Address a Test Case through `/api/v1/guardrails/{guardrailId}/test-cases/{caseId}`. Query a test run with its returned `runId`. The `caseId` of a Test Case is not the `runId` of a test run.
