Endpoint 默认要求应用、Agent 或网关进行凭据认证，并选择检测协议。不同信任边界需要独立凭据，调用方提供的 Header 不能代替认证。

例如，客服应用与内部测试网关分别使用自己的 Endpoint，运行记录才能区分它们的调用。

<a id="endpoint-integration-types" />
## 选择接入类型

两种类型都支持默认开启的“要求 Credential”开关，并由绑定的 Router 选择 Guardrail Version。关闭后请求以匿名身份进入检测流程，已有凭据仍保留。

| 类型 | 适用调用方 | 检测契约 |
| --- | --- | --- |
| LiteLLM（`litellm-generic-guardrail`） | LiteLLM 或实现其 Generic Guardrail 契约的调用方 | HTTP 检查非流式 Input 与完整的 Output，WebSocket 检查流式 Output。HTTP 使用 `x-api-key` 认证。 |
| Scan（`f5-scan`） | 独立文本检查、脚本或数据集评测 | 通过 `input` 提交文本，`scanDirection=request` 或 `response` 选择方向。使用该 Endpoint 的 Bearer 凭据认证。 |

共享的 `litellm_call_id` 关联 Input 与 Output。未提供时，两次检测不会共享固定的调用上下文。每次 Scan 请求彼此独立，两种协议都不生成业务模型回答。

[LiteLLM Provider 示例](/document/developer/gateway-connect#gateway-litellm-provider-example)实现了网关契约。其流式支持要求 fail-closed、Enforce 模式，以及 full 或 window 缓冲。

地址、凭据与验证步骤参见 [Endpoint 接入指南](/document/developer/endpoint-setup)。调用方必须在内容继续流转前执行检测结果。

<a id="state-endpoint" />
## 区分启停、接入进度与健康

<StateMachineDiagram kind="endpoint" locale="zh-CN" />

| 维度 | 含义 |
| --- | --- |
| 启停 | 保存为 `active` 或 `disabled`，有权限的用户可以修改。软删除是另一条件。 |
| 接入进度 | 如 `applying`、`awaiting_callback`、`verified` 或 `disabled`。 |
| 运行健康 | 如 `healthy`、`waiting` 或 `degraded`，来自运行观察。 |

接入验证成功不能证明真实流量健康。还要检查凭据、Router 下发和检测结果。凭据的签发、轮换与撤销仍是独立操作。

<a id="state-credentials" />
## 凭据与 Decision 不属于资源状态

个人 Access Token 授权管理调用，Endpoint 凭据授权运行时检测。每种凭据都有自己的签发与撤销状态。

allow、transform 和 block 描述一次检测结果，不会改变 Endpoint 或 Router 的生命周期。
