<strong>是什么：</strong>将一个或多个 Endpoints 的流量送往 Guardrail Versions 的可发布配置，包含有序 Routes、Selectors 和加权 Targets。

<strong>为什么：</strong>保护内容的版本与流量切换分离，才能灰度、回滚和审计。Route 按顺序 first-match-wins，fallback 在最后。

<strong>怎么用：</strong>保存草稿、预览、发布为不可变 Router Revision；确认 Runner 应用目标 generation，才认为新流量已切换。

<strong>例子：</strong>一个 Route 可把 90% 流量送到 Guardrail v1、10% 送到 v2 做灰度；命中哪个 Route 仍取决于 Selector 和顺序。

<a id="term-traffic-scope" />

## Selector

Traffic Scope · 流量范围 · 路由条件

基于可信请求事实构造的 AND/OR 路由表达式。

Selector 定义 Route 的匹配条件；fallback 无条件匹配。可选字段取决于绑定 Endpoint 的协议能力，外部 headers 不天然可信。

例如按已认证的 `endpoint.id` 或协议类型 `protocol` 选择 Route；如果条件都不匹配，就落到最后的 fallback。

<a id="state-router" />

## Router 下发状态机

<StateMachineDiagram kind="router" locale="zh-CN" />

Router 状态<strong>不是 Router Revision 内保存的字段</strong>，而是 Controller 根据 activeRevision、desiredGeneration、默认池 Runner 的应用确认和最近心跳推导：未发布为 unpublished；发布或回滚生成新 revision / generation 后为 distributing；至少有一个 Runner，且全部应用目标 generation、心跳有效时为 active；未收敛并有 rolloutError 时为 failed。失败后重新发布会清除旧错误并重新下发；active 遇到心跳过期或新 Runner 尚未追上，也会退回 distributing（若仍有错误则 failed）。旧 revision 是 historical，不代表它曾成功下发。

<a id="router-rollout-states" />

### Router 下发状态详解

以下卡片解释状态含义，不表示当前系统的实时状态。Router 状态由 Controller 根据 revision、generation、Runner 确认与心跳推导；它不是 RouterRevision protobuf 中的生命周期枚举。

<StateDetail label="状态变化">

首次发布生成 revision 和 desired generation，进入 distributing。

</StateDetail>

<StateDetail label="下一步">

完成 Route 和 Target 配置后发布。

</StateDetail>

</StateCard>

<StateCard title="正在下发" code="distributing">

<StateDetail label="含义">

已有活动 revision，但默认池 Runner 尚未全部确认当前 generation，或心跳已过期。

</StateDetail>

<StateDetail label="状态变化">

所有 Runner 确认且心跳有效后进入 active；未收敛且存在下发错误时进入 failed。

</StateDetail>

<StateDetail label="下一步">

检查 Runner 连接、预热过程及 desired/applied generation。

</StateDetail>

</StateCard>

<StateCard title="已生效" code="active">

<StateDetail label="含义">

默认池至少有一个 Runner，所有 Runner 已应用目标 generation 或更新版本，且心跳有效。

</StateDetail>

<StateDetail label="状态变化">

发布新 revision 后重新检查收敛；心跳过期或未应用新 generation 时不再视为 active。

</StateDetail>

<StateDetail label="下一步">

观察流量和运行日志；进行中的调用仍使用开始时固定的版本。

</StateDetail>

</StateCard>

<StateCard title="下发失败" code="failed">

<StateDetail label="含义">

当前 generation 尚未收敛，并记录了下发错误；不能据此认为所有 Runner 都已停止服务。

</StateDetail>

<StateDetail label="状态变化">

修复后重新发布会清除旧错误并重新下发；全部 Runner 有效确认后进入 active。

</StateDetail>

<StateDetail label="下一步">

查看 rolloutError 和 Runner 拒绝原因，修复依赖或配置后重新发布。

</StateDetail>

</StateCard>

</StateCards>

> 协议中的 DesiredStateResult.accepted 只有在整代配置预热并原子切换后才为 true。Runner 拒绝该代配置时，继续保留之前已应用的配置。这里的确认不同于发布 API 已接受请求。
