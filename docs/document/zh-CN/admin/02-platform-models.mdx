平台管理员配置共享模型服务和检测器绑定。业务用户在 Guardrail 中选择这些能力。

Default 无需检测模型，使用已审查的本地 Rule。模型 Policy 仍可用于其他 Guardrail。本地匹配不能替代模型的语义识别。

<a id="platform-model-steps" />
## 按顺序配置依赖

1. 在[模型提供商](/settings/providers)注册服务地址和凭据。
2. 检查连接。私有 CA 与 TLS 设置仅作用于该 Provider。
3. 在[模型](/settings/models)注册物理模型，并设置并发度，默认 2。
4. 执行真实调用测试。发现模型不代表它可调用。使用**测试全部模型**可逐个对已登记模型执行真实调用，并得到一份可达性汇总。
5. 在[防护能力](/settings/protection-capabilities)为兼容能力绑定 Model。
6. 保存绑定，再审查并应用配置。验证为可选操作。
7. 在[平台健康](/settings/health)查看应用进度。

防护能力按 Capability 展示，每项能力一行。输入和输出默认共用模型，点击**分阶段配置**可分别选择。已有的不同模型绑定会保留。共用模型须同时支持两阶段；JEV 和 Laya 内容安全均可共用模型或分阶段配置。

每项能力提供独立的**验证**和**保存**按钮。验证为可选操作，会分别检查各个已配置阶段并展示输入、输出结果。**保存**会依次保存阶段绑定；某阶段保存失败时，会保留该阶段的选择和错误以便重试。已保存的绑定无需验证即可审查并应用，验证失败也不阻止应用。输入和输出仍各自要求兼容契约，验证结果与应用状态分别保留。

健康检查关注运行基线和已启用发布路由使用的绑定。未使用的配置和历史版本不会让本地安装变为不健康。

管理员可激活未测试或失败的绑定。激活保留实际结果，不证明检测通过。发布前仍需验证自己的正反样例。

<a id="platform-model-deadlines" />
### 执行时限

模型并发度可设为 1–64。同一 Runner 中，引用同一注册模型的多个检查和请求共享这个额度，不同模型可并行执行。排队时间计入执行时限；请求短路后，排队中的模型调用会取消。

已绑定模型的并发度也可以在模型配置中单独修改。保存后通过配置下发到 Runner，无需重新做模型行为测试。该额度按 Runner 计算，多 Runner 的额度不会合并成 Provider 全局配额。

远程检测器模块的执行预算上限为 30 秒，能力探测使用相同上限。Model 配置中的更长超时不会延长该预算。超时不能计为通过的检测依据。

在 NVIDIA 托管的 `nvidia/nemotron-3.5-lightning-30b-a3b` 上执行 Grounding 时，适配器关闭可选 thinking。此设置仅适用于该适配器，不改变可迁移的 Policy 定义。

<a id="platform-model-evidence" />
### 用验证证据区分责任

每次 Validate 都会保留每个样本的请求与响应，无论通过或失败。打开 **失败证据** 或 **通过证据** 可查看实际接口地址、请求正文、请求头、响应正文、状态码、耗时、提示词版本与配置阈值。凭据已脱敏，导出保留完整 JSON。

失败样本会给出一个归因，而不是只显示“失败”：

- **模型能力** — 协议返回正确，但判断方向错误。
- **阈值** — 分数落在配置的灰区内，当前操作点未确认判断，不属于模型质量结论。
- **协议** — 返回不符合约定结构与标签，按适配或部署不一致处理，不代表检测质量。
- **接口** — 调用失败或在返回可用响应前超时，属于平台、网络或服务可用性问题。
- **配置** — 凭据、权限、接口地址或模型 ID 不允许此次调用。
- **平台** — Runner 或 Guard 在执行中失败。

归因来自已采集的证据，不会改变通过/失败结果；两个烟雾样本仍不能代表整项能力的检测质量。灰区样本即使被 Policy 兜底阻断，也保持未通过验证。

<a id="platform-model-boundary" />
## 区分能力绑定与 Policy

能力绑定提供检测器依赖，Policy 定义可复用的保护行为。模型连接成功不能证明某条 Rule 能识别目标内容。

已注册的 Generic chat Model（包括 DeepSeek）也可绑定到**分类灰区复核**，并保留原有 Control Plane 用途。内置提示词自动带上原判定标准、待检查的输入/输出和上下文；在支持复核的 Guard Policy 绑定中开启 `review_unknown=true`，即可复核 JEV/Laya 输入或内容安全输出的灰区结果。两阶段可共用或分别选择模型，验证结果保持独立。第一阶段检测仍需对应的专用协议。Controller 只下发生效数据面绑定引用的 Model 和凭据。

证明服务配置及已知结果的验证样例见[形式验证](/document/operator/operator-create-policy#operator-policy-formal-service)。部署与协议细节保留在仓库的 `docs/model-configuration.md`。
