审计日志回答“谁或哪个系统在什么时候，对哪个资源做了什么”。例如 Policy 测试、Guardrail 发布、Router 回滚或凭据变更，这些控制面事件可以用来还原变更的顺序。它不记录每次模型请求的 Decision。这类结果要看[运行日志](/document/admin/concept-logs)。

<a id="audit-how-to-use" />

## 从一次变更查到真实流量

例如某个 Router 将流量从 Guardrail v1 切到 v2：

1. 在审计日志按时间、**人员／系统**和资源 ID 查找 Router 的发布或回滚事件，打开详情核对事件类型、操作者与附加信息。有些事件由系统执行，操作者会显示为“系统”。
2. 到 [Routers](/integration/routers) 核对新 revision、Target 和 Runner 下发状态。审计事件证明发生了管理动作，不证明 Runner 已应用。
3. 到[运行日志](/document/admin/concept-logs)按 Guardrail 和时间范围查看切换后的真实请求，确认其固定版本与决策。

<a id="audit-scope" />

## 页面记录的范围

搜索和筛选由服务端执行，范围覆盖所选时间内已保留的审计事件，不限于最新 500 条。页面展示匹配总数，可选择每页 25、50 或 100 条。

- **搜索**：输入事件、操作者 ID、资源 ID 或变更详情中的关键词，点击“搜索”或按 Enter。
- **时间范围**：选择最近 24 小时、7 天、30 天或全部保留时间。
- **筛选**：展开后选择操作者类型、事件类型和资源类型。已选的条件可以单独移除，也可以一键清除。
- **查看详情**：点击事件名称或记录行，在右侧抽屉查看记录的变更，不离开当前查询。

例如，要找某个 Router 最近 30 天的发布记录：选择“最近 30 天”，在筛选中选择 Router 资源类型和对应发布事件，再搜索该 Router 的 ID。

查询条件、页码和查询截止时间保存在 URL 中，可以刷新页面、使用前进后退或分享链接。翻页期间截止时间固定，避免新日志插入导致记录移位。点击“刷新”会保留筛选条件、更新截止时间，并返回第一页。截止时间会显示在表格上方。
