审计日志按操作者、时间和资源记录管理变更。管理员通过 **访问与审计 → 审计日志** 查看。业务用户不能读取此页面或 API。

请求 Decision 与已采集正文属于用户的[运行日志工作区](/document/admin/concept-logs)。

<a id="audit-how-to-use" />
## 从管理变更追踪到流量

以 Router 在两个不可变 Guardrail 修订间切换 为例：

1. 管理员按时间、操作者和资源 ID 查找发布或回滚事件。
2. 打开事件详情，检查类型、操作者和记录的变更。系统操作以“系统”标识执行人。
3. 业务用户在 [Routers](/integration/routers) 核对 revision、Target 和下发状态。
4. 业务用户在[运行日志](/logs)核对变更后的实际版本和 Decision。

审计事件证明管理动作发生，不证明配置下发完成或应用已正确交付。

<a id="audit-scope" />
## 搜索和查看保留事件

搜索在服务端执行，覆盖所选时段的已保留事件。结果包含匹配总数，支持每页 25、50 或 100 条。

| 控件 | 用法 |
| --- | --- |
| 搜索 | 输入事件文本、操作者 ID、资源 ID 或变更详情。选择“搜索”或按 Enter。 |
| 时间范围 | 选择最近 24 小时、7 天、30 天或全部保留时间。 |
| 筛选 | 选择操作者、事件和资源类型，可单独或一起移除条件。 |
| 详情 | 打开事件名称或记录行，在右侧抽屉查看。 |

查找 Router 近期发布时，先选择 30 天。按资源和发布事件类型筛选，再搜索 Router ID。

<a id="audit-pagination" />
### 翻页时保持查询稳定

URL 保留筛选条件、页码和查询截止时间。翻页固定截止时间，避免新事件导致已有记录移位。

刷新会保留筛选、更新截止时间并返回第一页。表格展示截止时间。浏览器前进和后退可恢复查询状态。
