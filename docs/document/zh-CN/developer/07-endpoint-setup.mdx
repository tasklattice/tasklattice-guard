应用接入 Guard 从这里开始：选择检测协议、取得 Endpoint 地址和凭据，再验证实际交付。

资源编辑与发布自动化见[控制面 API 集成](/document/developer/developer-api-access)。

<a id="endpoint-protocols" />
## 选择检测协议

两类 Endpoint 默认要求凭据认证，并通过已发布 Router 选择 Guardrail Version。

| 类型 | 认证 | Input 与完整的 Output | 流式 Output | 调用关联 |
| --- | --- | --- | --- | --- |
| [LiteLLM 规范](/document/developer/gateway-connect) | `x-api-key` | 支持 | WebSocket 扩展 | 同一 Call ID 可在 Input 和 Output 之间固定版本。 |
| [Scan，F5 兼容](/document/developer/scan-protocol) | Bearer 凭据 | 支持 | 不支持 | 每次扫描独立分配路由。 |

自研网关或 Agent 可实现 LiteLLM 契约，无需部署 LiteLLM。HTTP 是传输方式，不是第三种 Endpoint 类型。字段、错误和结果处理以对应协议文档为准。

<a id="endpoint-prepare" />
## 取得地址与凭据

1. 确认目标 Guardrail Version 已 Released，依赖可用。
2. 准备指向该确切版本的已发布 Router。
3. 在 [Endpoints](/$projectId/integration/endpoints) 创建 Endpoint，选择类型和 Router。
4. 开启“要求 Credential”时，安全保存显示的完整凭据。复制运行时地址，保留 `/runtime/v1/endpoints/<endpoint_id>`。
5. 测试流量前，确认运行环境已应用配置。

检测请求使用 Endpoint 凭据，不能用个人管理 Token 代替。调用方提供的 Header 或 JSON 声明不会自动建立可信身份。

<a id="endpoint-credential-requirement" />
### 是否要求 Credential

创建和详情页的“要求 Credential”默认开启。管理 API 使用 `credentialRequired`，创建时省略默认为 `true`，PATCH 省略保持原值。

关闭后，LiteLLM HTTP、`/verify`、WebSocket 和 Scan 允许匿名调用，已携带的凭据也会被忽略。接入示例省略认证 Header；Scan 无需配置 `CALYPSOAI_TOKEN`。Router 与 Guardrail 检测继续执行。匿名请求不设置 `auth.principal`，可使用 `endpoint.id` 区分接入，依赖认证身份的路由条件不会因此获得身份。

Endpoint 始终生成并至少保留一个有效凭据。关闭认证不会撤销凭据，重新开启后原凭据仍然可用。若未保存完整值，可先在详情中生成新凭据，再开启认证。

设置在 Runner 应用后影响新请求和新 WebSocket 连接；已有请求和流按原流程结束。匿名与认证调用的 Call ID 上下文分别关联。

<a id="endpoint-address-configuration" />
### 部署地址设置

管理员可设置 Helm `runner.publicUrl`，对应 `CONTROLLER_RUNTIME_PUBLIC_URL`。Helm 也可继承顶层 `publicUrl`。没有覆盖值时，生成的地址使用当前 Controller 请求的来源地址。

反向代理需传递正确的外部域名和协议。将 `/runtime/v1/endpoints/` 转发到运行时服务，其余界面和管理路径转发到 Controller。内部调用单独使用 `CONTROLLER_RUNTIME_SERVICE_URL`。

请复制完整 Endpoint 地址。控制台域名本身可能不是运行时地址。

<a id="endpoint-litellm" />
## 通过 LiteLLM Provider 示例接入

TaskLattice LiteLLM 镜像包含 TaskLattice Guard Provider。连接设置属于 LiteLLM，Endpoint 详情不展示其实时配置。

1. 在 LiteLLM 管理界面打开 **Guardrails → Guardrail Garden → TaskLattice Guard → Create Guardrail**。
2. 填写 Endpoint 地址与完整 Secret。
3. 选择检测点和故障处理方式。
4. 选择 **Verify & connect**。Provider 应用配置，无需重启。
5. 发送真实 Input 和 Output 检测，核对 Endpoint 运行活动与客户端实际交付。

`/verify` 检查 Endpoint 访问权限和适配器兼容性；开启凭据要求时校验凭据，不执行 Policy 检测。

| Provider 设置 | 默认值 | 行为 |
| --- | --- | --- |
| Inspection points | 按接入场景选择 | Before model 检测 Input，After model 检测 Output。受保护的流式接入要求两者都开启。 |
| Guard unavailable | Block request | Continue without protection 仅适用于非流式回调中允许降级的故障。 |
| Runtime timeout | 10 秒 | 范围为 1–60 秒。 |
| Apply to every request | 开启 | 仅在调用方显式选择 Guardrail 时关闭。 |

非流式回调允许降级的故障包括网络错误、超时及 HTTP 502、503、504，不包括 Policy 阻断、4xx、500 或无效响应。

受保护的流式接入要求 **Block request**、两个检测点均开启，并使用 **Enforce**。示例 Provider 支持 `full_buffered` 和 `window_buffered`，拒绝 `interruptible`。业务客户端继续使用 SSE，Provider 通过 WebSocket 与 Guard 通信。

复用示例前，请阅读 [Provider 限制](/document/developer/gateway-connect#gateway-litellm-provider-limits)。其他网关可通过自己的适配器实现[协议契约](/document/developer/gateway-connect)。

<a id="endpoint-scan" />
## 接入 Scan

将 `CALYPSOAI_URL` 设为完整 Endpoint 基础地址，将 `CALYPSOAI_TOKEN` 设为对应的完整凭据。拼接 `/backend/v1/scans` 时，需保留 Endpoint 路径。

具备 Endpoint 写权限的用户可配置“默认 flagOnly”。新建 Endpoint 默认为 `true`。请求省略字段时使用此配置，显式布尔值优先。

使用 [Scan 请求示例](/document/developer/scan-protocol#scan-connection)提交真实扫描。Scan 不支持 `/verify`。兼容占位字段不能选择项目、配置 Scanner 或关联请求。

<a id="endpoint-delivery" />
## 在模型调用前后执行结果

调用模型前先检测 Input，并执行阻断或替换。完整的 Output 在交付前检测。流式 Output 只交付 Guard 已释放的 `delta.text`。

必须读取 LiteLLM 的 `action` 或 Scan 的 `result.outcome`。HTTP `200` 或 Python `raise_for_status()` 成功不能单独作为交付依据。未知值、无效 JSON 和超时不证明检测通过。

Fail-closed 在缺少有效结果时停止流程。Fail-open 只适用于接入方明确允许降级的故障，不能把阻断、替换或标记解释为通过。

Guardrail 的 Monitor 和 Bypass 有独立语义，可能返回原文而不执行干预。评估保护时需核对模式。模型调用、重试、取消和最终交付由应用负责。

<a id="endpoint-verification" />
## 验证实际交付

对照预期明确的样例、[运行日志](/$projectId/logs)和实际交付内容。版本已发布、配置已应用、调用方正确接入是三个独立条件。

| 验证项 | LiteLLM 规范 | Scan |
| --- | --- | --- |
| 认证与执行 | 验证连接后，检测真实 Input 和 Output。 | 提交真实 request 与 response 扫描。 |
| 结果处理 | 处理三种 action 和替换数组。 | 处理四种 outcome 与 Endpoint 默认值。 |
| 关联 | 测试同一 Call ID 和过期上下文。 | 确认扫描互相独立。 |
| 交付 | 核对替换文本与服务端释放的流式文本。 | 等完整 JSON 返回后执行 outcome。 |
| 故障 | 测试凭据、字段类型、上下文过期、断线和无效替换。 | 测试凭据、类型、正文上限、媒体类型、检测失败和超时。 |

Endpoint 的 Verified 接入状态需要实际检测流量。一个方向成功不证明另一个方向已执行。评测报告需分开记录执行故障和内容判定。

<a id="endpoint-credentials" />
## 轮换凭据或停用 Endpoint

1. 选择“生成新凭据”，安全保存完整值。
2. 更新应用凭据。
3. 使用新凭据发送真实请求。
4. 验证成功后撤销旧凭据，至少保留一个有效凭据。

凭据提示不能还原密钥。关闭“接收回调”后，所有检测请求（包括匿名请求）都会被拒绝。
