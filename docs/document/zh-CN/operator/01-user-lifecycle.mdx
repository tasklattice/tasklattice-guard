保护一个业务场景时，先复用经过审查的 Policy，再组合、测试和发布 Guardrail。当前控制台的创建和发布入口需要管理员权限。这里按运维任务组织操作步骤，不代表所有登录角色都能执行写入。

1. **浏览 Policy Library** — 阅读 Policy 的用途、Rules、参数和 Test Cases，确认它能表达所需保护行为。

2. **创建 Guardrail** — 描述业务用途和边界，选择 Policy Version，并确认实际启用的 Rules 与 Rails。

3. **运行测试** — 让当前草稿的 Test Case 通过与生产相同的 NeMo 运行时，生成测试报告。失败的结果也会保留为证据。

4. **发布版本** — 把已通过验证的草稿固化为不可变 Guardrail Version。后续修改不会改变已有版本。

5. **接入业务流量** — 为应用准备 Endpoint，把 Router 的 Route 指向该固定版本，发布后确认 Runner 已应用目标配置。

6. **复盘与改进** — 在 Playground 试用行为，根据运行日志与审计证据调整下一版策略。

**Ready（就绪）**表示至少保留一个在本环境已发布的不可变版本，且仍有匹配的本环境 Passed 报告；不表示草稿已通过测试或流量正在使用它。首页分别展示就绪性、版本容量和具体流量引用。导入的 Guardrail 使用相同操作流程，导入版本先为 Pending，在本环境测试后显式 Release。删除、恢复与测试依据的完整规则见 [Guardrail 生命周期与就绪性](/document/overview/term-guardrail#state-guardrail-readiness)。
