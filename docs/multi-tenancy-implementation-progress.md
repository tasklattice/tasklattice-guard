## Principles

- Retain tenant groups: A and B may share a group and Runner pool, while C may be assigned another group. Membership does not grant resource sharing. A group is a Runner trust domain; hard process isolation between its members requires separate pools or another isolation layer.
- Existing logical isolation, data, local runtime state and unrelated uncommitted changes must be preserved. The working tree is based on `6044b72`; it already contains substantial uncommitted tenant-group/lab work. Do not overwrite, reset or silently change it.
- Fail closed when a tenant, Runner identity or trusted attribution is absent or contradictory. Explicit platform and background operations require explicit authority; avoid guessing ownership for historical data.
- Test behavior at its actual boundary. Keep local fake traffic and production admission controls distinguishable. Report what a test proves and what remains shared or unverified.
- Never write credentials or private configuration to tracked files or logs. Do not commit or push unless the user explicitly authorizes that action in the current request.

### Lease integration design — still outstanding

- Persist grants independently of `runner_instance`: registration is keyed by Runner ID and can overwrite an older boot. Under the existing allocation advisory lock, Controller must durably record each authorized pool/runner/boot/epoch/nonce grant and its conservative expiry before acknowledging it. Never erase or shorten outstanding old grants just because a stream disconnects or a replacement boot registers.
- A move needs a persistent two-stage drain and epoch transition. Stop old grants, then wait outside the database lock for all old leases plus a justified uncertainty bound, or verify external workload/network fencing, before enabling the new assignment. Coordinate all Controllers via the same database lock; recover pending moves on restart.
- Runner must activate and acknowledge the exact Controller-dispatched state, then accept only authenticated, nonce-matching grants; `DesiredStateResult` must not be able to claim a future generation. Cancel/fence all work paths (including jobs that bypass ASGI), and reject stale grant responses. Suspend/uncooperative-worker assumptions require infrastructure enforcement, not just the standalone Python timer.
- Next implementation: agree on protocol capability negotiation and storage schema with milestones 1/3, generate protobufs using repository scripts, implement the state machine and adversarial tests. No live lease protocol or move safety guarantee has yet been implemented.
